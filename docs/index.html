One Paystack or Flutterwave account. Many applications. Every webhook delivered to the right one.

Relay is a small self-hosted Go service. It receives your payment provider's webhooks, verifies them, decides which application owns each event, stores it safely, and delivers it to that application with its own signature.

Read the docs Try it in five minutes View on GitHub 
go install github.com/khaleelhabeeb/relay/cmd/relay@latest

The problem

Paystack and Flutterwave each send all webhooks for an account to one URL. If App A, App B and App C share that account, something at that URL has to work out which application each payment belongs to and pass the event on. Relay is that piece. It never guesses and never broadcasts payment data.

One binary, no infrastructure

Embedded SQLite. No Redis, no message queue, no dashboard to host.

Safe by default

Signatures are verified on the exact bytes the provider sent. Relay answers only after the event is committed to disk.

Language-agnostic

Your apps receive a plain signed HTTP POST. No SDK needed: verification code for Python, PHP, Node.js and Go.

Paystack and Flutterwave

Enable either, or both side by side, on /webhooks/paystack and /webhooks/flutterwave.

How it works

From the provider's webhook to a signed delivery your application can trust.

                            ┌──────────────────────── Relay ─────────────────────────┐
 Paystack    ── webhook ──▶ │ verify signature ─▶ find owner ─▶ save to SQLite ─▶ 200 │
 Flutterwave ── webhook ──▶ │                                          │             │
                            │                         delivery workers ◀┘             │
                            └──────────────┬──────────────────┬────────────────────────┘
                                           ▼                  ▼
                                         App A              App B         (signed POSTs,
                                                                          retried on failure)
  1. Receive. The provider posts a webhook to Relay.
  2. Verify. Relay checks the signature against the raw request body and rejects forgeries.
  3. Find the owner. By reference prefix, metadata, or references and virtual accounts your apps registered.
  4. Store. The event and the decision are saved in one transaction, and only then does Relay answer 200.
  5. Deliver. A worker sends the event to the owning app and retries with backoff for up to 24 hours.
No owner, or more than one? Relay holds the event as unresolved or ambiguous for you to resolve from the CLI.

Receive events in a few lines

Verify Relay's signature, deduplicate on X-Relay-Event-ID, respond quickly.

http.Handle("/webhooks/relay", receiver.Handler(secret, func(ctx context.Context, d *receiver.Delivery) error {
	// deduplicate on d.EventID, then process d.Body; an error makes Relay retry
	return nil
}))

Built to not lose payments

~3,400 webhooks/s

Accepted on an Apple M1 laptop with durable commits. A million charges a month is about 0.4 per second.

Crash tested

SIGKILLed mid-ingest and mid-delivery: no acknowledged event lost, every signature verified.
